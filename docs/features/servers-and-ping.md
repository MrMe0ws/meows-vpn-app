# Серверы и пинг

- Список серверов — `XKStore.servers()` (по конфигам подписки): `flag` (эмодзи-флаг из названия: флаг страны или пиратский 🏴‍☠️; на Windows картинки `resources/flags/<код>.png`, для пиратского — `pirate.png`), `title`, `subtitle` («VLESS · TCP · Reality · JSON»), `endpoints`.
- Выбранный сервер — `XKStore.index()/setIndex()`; при смене во время подключения VPN переподключается (`reconnectIfNeeded`).
- Строка (`ui/home/ServerRow.kt`): тап — выбрать, **свайп справа налево открывает кнопку «Пинг» (как в Telegram), пинг — нажатием на неё**, долгое нажатие — JSON-конфиг.

## Пинг
- Режимы: **реальный** (ядро `measure` делает запрос через сервер) и **TCP** — настройка `P_PING_MODE`; адрес проверки `P_PING_URL`. **Таймаут** выбирает пользователь (Настройки → Пинг: 3/5/6/8/10 с, `P_PING_TO`, по умолчанию **6 с** — `PING_TO_DEFAULT`); один и тот же для реального и TCP-пинга. Windows: пока фиксированные 6 с (`PingRunner`).
- API: `XKStore.pingAll`, `XKStore.pingSome(int[] only, …)`; результат в `XKStore.pings` (мс; −1 нет ответа; −2 UDP-протокол).
- VM: `ping()` (все), `pingOne(i)` (свайп; индикатор в строке — `pingingOne`). Показ результата скрывается через `P_PING_KEEP` секунд (0 — всегда).
- Почему не 3 с: при 3 с на медленной сети (роуминг, слабый LTE) все серверы показывали «нет ответа»; на Pixel 10 с SIM в роуминге при 8 с ответы были 440–720 мс. «Реальный» пинг — несколько круговых обходов (TCP + Reality + HTTP), при 800–900 мс до сервера он занимает 3–5 с. Результаты приходят по мере ответа серверов, ждут таймаута только недоступные.
- **Автопереключение** (`XKVpnService.watchLoop`): раз в 30 с пинг текущего сервера (те же 10 с); переключение после **трёх** неудач подряд при живой сети, не чаще 3 раз за 10 минут. Если не ответил ни один сервер — ничего не меняется.
- «Выбрать быстрейший» — меню шапки подписки, берёт минимальный положительный пинг.
- Приложение исключено из VPN, поэтому пинг честный и при включённом подключении.
