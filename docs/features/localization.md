# Язык интерфейса (русский / английский / авто)

Настройка «Язык» (Android — «Настройки → Язык», Windows — «Настройки → Язык»): **Авто** (по умолчанию), **Русский**, **English**. «Авто» берёт язык системы: русский → русский, любой другой → английский.

## Как устроено
- Тексты в коде остаются русскими и служат ключом: `tr("Настройки")`; шаблоны с подстановкой — `trf("Быстрейший: %s · %d мс", name, ms)`; слово «сервер» по числу — `serversWord(n)`.
- Перевод — словарь `i18n/EnDict1..7.kt` (`ключ по-русски to английский`); нет перевода → показываем русский текст. Android: `app/meows/vpn/i18n/`, Windows: `app/meows/desktop/i18n/` (словари одинаковые, правятся в обоих).
- `Lang.choice` — Compose-состояние: экраны, вызвавшие `tr`, перерисовываются при смене языка. Хранение: Android — `prefs "lang"`, Windows — `settings.json "lang"` (0 авто, 1 ru, 2 en).
- Из Java (уведомления, плитка, `XKStore`) — `Lang.tr(...)`; перед этим `Lang.init(context)` (в `MainActivity`, `XKReceiver`, `XKTileService`).
- Нельзя вызывать `tr` в статических `val` на верхнем уровне/в `enum`/`object` (значение зафиксируется на старте) — делать `get()` или функцию (пример: `Palettes.names`, `VpnMode.title`).
- **Не переводим:** журнал (`AppLog`, «Логи → События») и отчёт для поддержки (`Diagnostics.kt`) — их читает поддержка по-русски; сообщение «Сервер отдал ссылки вместо Xray JSON…» (по нему сравнивается текст ошибки).
- Android: подписи виджетов — ресурсы `values/strings.xml` и `values-en/strings.xml`, они следуют **языку системы**, а не выбору в приложении.

## Правило для новых текстов
Каждую видимую пользователю строку оборачивать в `tr(...)` и добавлять в `EnDict*.kt` обеих платформ.

## Не проверено
Все экраны на английском глазами не просмотрены: возможны длинные подписи, которые не влезают, и пропущенные строки (они останутся русскими).
