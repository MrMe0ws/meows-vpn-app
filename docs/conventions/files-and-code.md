# Файлы и код

## Размер и дробление
- Kotlin-файл **до ~150 строк**; больше — делим. Жёсткий потолок ~250.
- Один файл — одна смысловая единица: экран, раздел настроек, компонент, класс, набор мелких связанных функций.
- Composable, которая нужна только внутри файла — `private`. Нужна другим — выносим в `ui/components/` или в папку фичи.
- Сразу создавай файл в «правильной» папке. Не складывай новое в `MainActivity.kt`, `MeowsViewModel.kt` или `*Screen.kt` «потому что там удобно».
- `MeowsViewModel` тонкий: если фича разрастается (как `UpdateController`) — выноси в её пакет, VM только держит экземпляр.

## Папки
- `ui/<экран>/` — экран и его части. `ui/components/` — переиспользуемое. `ui/theme/` — тема.
- `ui/settings/pages/` — один файл на раздел настроек.
- `<фича>/` рядом с `ui/` (как `update/`) — логика без Compose.
- Легаси `XK*.java` лежит в корне пакета; новые Java-файлы не добавляем.

## Имена
- Файл = имя главной сущности (`ServerRow.kt` → `ServerRow`). Страницы настроек — `<Имя>Page`, экраны — `<Имя>Screen`.
- Ключи prefs — `camelCase`, константы рядом с фичей.
- Пакет совпадает с папкой.

## Комментарии
- KDoc `/** … */` на каждом публичном Composable/классе: **что делает и почему**, одной-двумя строками, по-русски.
- Комментарии — про «почему», не пересказ кода.

## Состояние и сайд-эффекты
- Composable не ходят в сеть/диск. Это делает VM/контроллеры (корутины, `Dispatchers.IO`).
- Настройки пишем через `vm.setFlag/setPref`, не напрямую в prefs из UI.

## Проверки перед «готово»
1. `.\android\build.ps1 -Debug` собирается без ошибок.
2. Обновлены `docs/architecture/structure.md` и профильный файл в `docs/`.
3. В отчёте честно сказано, что проверено на устройстве, а что нет.
