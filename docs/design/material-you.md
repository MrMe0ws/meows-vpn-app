# Material You (Material 3 Expressive) — принципы

Наш дизайн-закон. Источник: Material Design 3 / M3 Expressive (m3.material.io). Приложение должно выглядеть и вести себя
как «родное» приложение Android 12+/16, но с характером кота.

## Три идеи
1. **Персонализация.** Цвета берутся из обоев пользователя (dynamic color) или из выбранной палитры. Цвета не хардкодим — только роли `MaterialTheme.colorScheme.*`.
2. **Выразительность (Expressive).** Крупная типографика, скруглённые формы, живой «пружинный» мотион, эмоция в ключевых местах (кот-кнопка, лоадеры).
   Эмоции — в главном действии, а не везде: вторичные экраны остаются спокойными.
3. **Понятность.** Один главный акцент на экране, прогрессивное раскрытие (сложное — на подстраницах), крупные цели нажатия, предсказуемая навигация.

## Что обязательно
- Только компоненты Material 3 (`Button`, `FilledTonalButton`, `ListItem`, `Card`, `ModalBottomSheet`, `AlertDialog`, `SwipeToDismissBox`, `SegmentedButton`, `DropdownMenu`, `LoadingIndicator`, wavy-индикаторы …). Кастомный компонент — только если стандартного нет (кот-кнопка).
- Тема через `MeowsTheme`: цвета — роли, формы — `MaterialTheme.shapes`, шрифты — `MaterialTheme.typography`, анимации — `motionScheme` (expressive).
- Светлая и тёмная темы, AMOLED-чёрный для тёмной. Всё проверяем в обеих.
- Edge-to-edge: контент под системными панелями, отступы через `WindowInsets` (`statusBarsPadding`, `navigationBars`).
- Предиктивный жест «назад» (`BackHandler` там, где есть внутренняя навигация).
- Доступность: `contentDescription` у иконок-кнопок, контраст из цветовых ролей, цели нажатия ≥ 48dp, текст масштабируется (sp).
- Адаптивность: экран не должен ломаться на планшетах/складных; ширина контента на больших экранах ограничивается, а не растягивается.

## Чего не делаем
- Не красим элементы произвольными hex-цветами (исключение: логотип/иллюстрации и превью-свотчи палитр).
- Не делаем iOS-подобные/«стеклянные»/неоморфные элементы, кастомные тени и градиенты вместо тональных поверхностей.
- Не прячем главное действие в меню и не ставим два равноправных главных действия на экран.
- Не вкладываем скролл в скролл, не ставим длинные тексты в кнопки.
- Не придумываем свои жесты там, где есть стандартные (свайп-для-действия делаем через `SwipeToDismissBox`).

## Если просьба противоречит гайдлайнам
Скажи это прямо и коротко: что именно противоречит, чем плох результат для пользователя, и предложи альтернативу в духе Material You.
Если пользователь настаивает — делаем по его решению и записываем исключение в `docs/decisions.md`.
